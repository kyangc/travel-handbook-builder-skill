# Travel handbook authoring

Turn explicit source facts into supported typed operations while preserving unknowns, prior edits, and confirmed or completed facts. Interpret the supplied prose or JSON, then choose the operations that express it. The runtime does not parse prose or choose destinations, hotels, flights, places, daily themes, or routes. Record an explicit capability or data gap instead of inventing content.

## Locate and use the bundled runtime

Resolve every resource from this skill directory, never from the process working directory. In Kimi, the directory is `${KIMI_SKILL_DIR}`. In another agent, use the directory containing this `SKILL.md` as the equivalent root.

Read [installation and invocation](README.md) if the local environment is not prepared. The stable CLI is `scripts/travel-handbook`; `scripts/python` runs Python API callers with the bundled runtime on `PYTHONPATH`. Both launchers find the skill directory themselves and work from another current directory, including paths containing spaces.

Read [the caller guide](references/CALLER_GUIDE.md) before writing a request. Load only the topic guides needed for the supplied material from [the public guide index](references/README.md). Treat `read_workspace(state)["capabilities"]` as the live inventory. Schema fields and planned methods are not callable capabilities. Do not inspect runtime source, Schema, tests, or historical payloads to invent a calling protocol.

## Start or resume

- New work follows `new_workspace` or CLI `create`, then `trip.define`. New trips use the stable 1.0 data contract; never edit `schema_version` directly.
- Resume from the complete saved state JSON when available. It retains handles, receipts, source snapshots, bindings, decisions, and Issue resolution metadata. Save that complete state after every committed batch; it is the lossless continuation file.
- `export_package(...)` returns an export report. The canonical handbook JSON inside it is `export_report["package"]`; serialize that value for `import_package`. CLI `export` already writes only this canonical package. The complete report also contains validation, projection fields when applicable, and a manifest. If you retain it for diagnostics, use a distinct name such as `export-report.json` and never use it as import input.
- Use `import_package` or CLI `import` only for the canonical exported package; import cannot recover authoring-only metadata. Read [recovery, bounded read, and preview](references/RECOVERY_READ_PREVIEW_GUIDE.md) before either path. Use one writer per state file, and keep state, packages, and reports outside the installed skill directory.

## Read and write safely

- A read result exposes an object `handle` as a string. Existing-object writes normally use `{"handle": handle_string}`. Within one batch, refer to an earlier `as` alias with `{"local": "alias"}`. Use documented part references for owned local records; never substitute raw domain IDs.
- Set a new request's `expected_revision` from a current read. Replay a successful request only with the same `request_id` and identical payload. A different request ID is a new write.
- After each successful public write, preserve the exact original request object in caller-owned `request-journal.json`; continuation rounds must carry that journal forward outside the authoring state. Use the stored object unchanged for a same-request replay. Follow [the request-journal and replay procedure](references/RECOMMENDATION_ROUTE_DECISION_GUIDE.md); a receipt or reconstructed payload is not a substitute for the original request.
- Preserve an explicitly stated evidence kind in the typed Source used by downstream records. In particular, when material says a rate, path, or other evidence comes from a synthetic source, create a `source.record` with `kind: "synthetic_fixture"` and point the typed record to it. Keep the complete-text `source.register` snapshot as separate source-preservation evidence; its generic `other` kind does not replace the stated evidence identity. Do not label material synthetic unless the supplied source does.
- When a GuideNote paragraph comes from material that explicitly identifies itself as synthetic or fictional, every citation on that paragraph must preserve that attribution independently in its exported Source metadata. A `synthetic_fixture` citation does not make a generic snapshot citation synthetic. If an exact snapshot anchor is needed, include the literal label `synthetic` in the `source.register` snapshot title, while retaining any supplied `fictional` wording; otherwise cite only the `synthetic_fixture` Source. Never rely on another citation in the same paragraph to carry this warning.
- Recording an exchange rate does not activate it for budget projection. When the material explicitly says to adopt or use a direct `1 BASE = rate QUOTE` mapping for this budget conversion or budget view, the direction supplies `reporting_currency: QUOTE` when it does not conflict with the current configuration. Read the current budget first: `budget.configure` replaces the complete adopted-rate set. For the same reporting currency, submit the full preserved set and replace only a same-base rate that the source explicitly updates. If the current reporting currency conflicts and the source does not explicitly authorize a switch, record the ambiguity instead of overwriting it. Then inspect `budget_projection`. Do not configure a merely informational rate, infer an inverse or chained rate, or treat a budget rate as a settlement fact.
- Batches are atomic. On an `AuthoringError` or structured CLI error, inspect `code`, `op_index`, `parameter`, and validation paths. Retain the pre-call state, correct the input, and retry deliberately. Do not bypass a blocker by rewriting IDs, clearing history, reopening completed work, weakening evidence, or editing state directly.
- Omit unknown optional fields instead of sending `null` or inferred values. Older source material must not overwrite manual changes, done Tasks, resolved Issues, completed execution, or confirmed facts.
- Translate each source revision into the narrowest supported patch. When the source explicitly limits an edit, treat the named domain fields as the complete mutation set and omit every other field from the write. Preview the request, apply that same request, then read the target back and verify that the object-level diff stays within the authorized fields. Context that restates an unchanged or unknown fact is a preservation constraint, not authorization to rewrite that field. When an API requires replacing a composite value, carry its unchanged subfields forward exactly.
- Normalize an explicitly road-based shared passenger shuttle as `mode: "bus"`. This includes wording such as shuttle bus, shuttle coach, 接驳车, 接驳巴士, 摆渡车, or 班车. Choose scheduled versus independent separately from this mode classification: an unknown operator does not block a scheduled Service; explicit `service_number`, `service_date`, and valid Calls use the scheduled contract, even when some Call times are explicitly unknown. If the required service identity or legal Calls are unavailable, keep an independent bus Leg with the known endpoints and timing. Use `other` only when the supplied transport category is outside the canonical mode list or the word “shuttle” does not identify the vehicle category.
- When completeness matters, follow every read page until `pagination.has_more` is false. `related_handles` contains direct relationships, not a complete dependency graph.
- Use `preview` for a proposed batch, then submit the original request with `apply`. Preview handles are diagnostic. A preview conflict does not produce a signed credential for source conflict resolution.

## Route to the relevant guide

- If the supplied material includes complete source text, a recommendation whose Place identity may be unclear, a movement or return statement with a missing endpoint, an unconfirmed entrance, a Route segment with a stated clock/service fact, or distinct movement labels, first read [source preservation and authoring identity decisions](references/RECOMMENDATION_ROUTE_DECISION_GUIDE.md).
- Dates, times, unassigned selected items, moves, withdrawals, and execution replacement: [time](references/TIME_PLAN_GUIDE.md), [unassigned items](references/UNASSIGNED_ITEM_GUIDE.md), and [arrangement edits](references/ARRANGEMENT_EDIT_GUIDE.md).
- Places, entrances, stays, recommendations, and shopping with an unknown shop: [locations](references/LOCATION_GUIDE.md), [access points](references/ACCESS_POINT_GUIDE.md), [stays](references/STAY_GUIDE.md), [recommendations](references/RECOMMENDATION_GUIDE.md), and [shopping places](references/SHOPPING_PLACE_GUIDE.md).
- Movement, scheduled transport, owned vehicles, and paths: [movement](references/MOVEMENT_GUIDE.md), [transport services](references/TRANSPORT_SERVICE_GUIDE.md), and the related guides in the [public guide index](references/README.md).
- Participants, costs, reservations, benefits, tasks, Issues, notes, opening hours, and coverage revisions: load only the matching guide from the public index.
- Later versions of the same source: use the bounded [source adoption protocol](references/SOURCE_ADOPTION_GUIDE.md) for its supported identities and field aspects, or the duration-only [source refresh guide](references/SOURCE_GUIDE.md). Preserve stable `(document_key, semantic_key)` identities and submit only supported fields. There is no general synchronization, graph patch, automatic route choice, or permission to restore tombstoned topology.
- GuideNote citations: read [the note and citation guide](references/GUIDE_NOTE_GUIDE.md). Read/export citations are output records, not valid write inputs. Rebuild write citations from a Source handle or exact stored-snapshot anchor.

## Check, export, and account for the source

After meaningful writes, run `check` and inspect errors, warnings, and affected projections. Before export, read the current revision and pass that revision to `export`. The export is private and may contain sensitive material. Its manifest reports `source_coverage=not_assessed`; that does not authorize publication.

Separately reconcile the supplied material against the result. For every relevant explicit statement, identify its typed destination, a preserved original-text note or citation, or a recorded capability/data gap. A canonical GuideNote can preserve an unidentified suggestion, but it does not count as a typed Recommendation; record that typed gap separately. Confirm that facts outside the requested change remain intact. Structural validity and successful export do not prove source completeness, factual accuracy, travel feasibility, booking status, or readiness for public release.
